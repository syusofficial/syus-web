## 3. 클라이언트 env-throw 패턴 (env 비면 throw → 컴포넌트 사망)

`src/lib/supabase/client.ts:14-28` — 현재 상태:
```ts
export function createClient() {
  const url = process.env.NEXT_PUBLIC_SUPABASE_URL;
  const anonKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY;
  if (!url || !anonKey) {
    console.error("[supabase] 환경변수 누락 …");
    throw new Error("Supabase 환경변수가 설정되지 않았습니다.");  // ← 여전히 throw
  }
  return createBrowserClient(url, anonKey);
}
```

**호출 위치 전수 (15곳) — 전부 useEffect 또는 이벤트 핸들러 내부:**
Footer·NavMega·LikeButton·RatingInput·SessionManager·ShowViewTracker·SocialLoginButtons·RealtimePresence·PageViewTracker·LivePresenceCard·Nav. 렌더 본문에서 직접 호출하는 곳은 **0건.**

**판정 — 중간:**
- 라이브(Vercel)엔 env가 정상 주입돼 있어 **평소 동작엔 영향 없음.**
- env가 비는 비정상 상황에서도, throw가 **렌더 중이 아니라 useEffect/handler 안**에서 터지므로 React 트리 전체가 무너지지 않는다. 해당 컴포넌트의 부수효과(auth 구독·좋아요 등)만 실패하고 화면·클릭은 유지된다.
- 따라서 "전역 마비" 등급은 아니다. 다만 **fail-fast throw는 여전히 잠재적 단일 장애점의 씨앗**이다. 만약 향후 누군가 `createClient()`를 렌더 본문이나 useMemo 초기값에서 호출하면 그 순간 트리가 죽는다. (지금은 규율로만 막혀 있고 구조로는 안 막혀 있음.)
- **권고:** throw 대신 `null` 반환 + 호출부 옵셔널 처리. 또는 ErrorBoundary(§4)로 감싸 throw가 나도 전체가 안 죽게. (§4가 더 근본적.)

`middleware.ts`·`server.ts`·route handler들의 `process.env...!` non-null 단언(11곳)은 **서버 사이드**라 클라이언트 마비와 무관. 단 빌드 가드는 없음(누락 시 런타임 500). `admin.ts`는 캐시+호출시점 throw로 적절히 처리됨.

지금 당장 throw하는 코드가 렌더 본문에 없다는 건 §2·§3에서 확인했지만, **안전망 부재 자체가 구조적 취약점**이다. 향후 어떤 수정이든 렌더 중 throw를 한 줄 들이면 즉시 전체 마비로 이어진다.
